## 1. Direction and evidence boundaries

Make Kaneo feel like a familiar spreadsheet database, not a new interaction language. Adopt NocoDB's select-first grid, typed Field controls, predictable toolbar, saved views and expanded Row.[2][][14][][16][] Do **not** copy its entire platform or equate every advertised Cloud capability with the open-source edition. This is a behavioral comparison, not permission to copy source or a license assessment.

Use Kaneo nouns: **Ticket**, **Table**, **Row**, **Field**. In NocoDB citations, “record” means Row and “column” means Field; “view” is a saved presentation of the same Rows, not a second Table. A **primary/display Field** is a human label, not an internal Row ID. NocoDB explicitly distinguishes display values from technical primary keys. [1][]

The early criticism in [table-feature-discovery.md:7–89](table-feature-discovery.md#L7) describes the old text-only implementation. Its owner pivot at [190–287](table-feature-discovery.md#L190) supersedes the recommendation to retire standalone Tables. The inspected code now has typed physical PostgreSQL columns, virtualization, grid selection, filters, groups, summaries, Ticket references, CSV and history; these are not missing foundations. [fields.ts:4–48](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/api/src/data-table/fields.ts#L4) [store.ts:155–186](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/api/src/data-table/store.ts#L155) [data-table-grid.tsx:596–784](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/web/src/components/data-table/data-table-grid.tsx#L596)

Missing capabilities mean “no contract/control found in the inspected Table paths,” not a claim about every Kaneo subsystem. ## 7. Source architecture lessons, not a rewrite

- **Separate data from view configuration.** NocoDB `View` identifies its Table, type and lock/share attributes; `GridViewColumn` carries order/show/width/grouping/aggregation. Kaneo's current local state is not that persisted model. Add one small view model rather than another set of browser keys per feature. [62][] [63][] [data-table-grid.tsx:596–615](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/web/src/components/data-table/data-table-grid.tsx#L596)
- **Model filter structure explicitly.** NocoDB Filter stores parent, group and logical operation; copying its visual nesting without a matching server expression tree would be false parity. [64][] [index.ts:63–76](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/api/src/data-table/index.ts#L63)
- **Keep Field metadata and derived dependencies distinct.** NocoDB Column has `uidt`/DB type/default/description, while relation/Lookup/Rollup models hold references. Kaneo already controls generated SQL identifiers and transactional DDL; retain that safety boundary and let W5 own relations. [65][] [66][] [67][] [68][] [store.ts:99–186](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/api/src/data-table/store.ts#L99)
- **Borrow the contract, not the framework.** Canvas range/fill behavior is useful evidence, not a reason to replace Kaneo's virtualized DOM grid with Vue/canvas. Existing focus, typed editors, resize controls and history should remain the shared path. [58][] [59][] [data-table-grid.tsx:763–886](https://github.com/IEatCodeDaily/kaneo/blob/cc09fe5684aed5cdf943ee00938f42b86779b00c/apps/web/src/components/data-table/data-table-grid.tsx#L763)

## 9. Prioritised next 10 (verbatim handoff backlog)

Ranking is product judgement by user value relative to effort, not a measured score. Items already assigned to W1–W8 are excluded; dependencies are explicit. Each render state below is **proposed**, not an existing test name.

1. **Complete spreadsheet keyboard navigation (M).** Integration: edit/clear through the real API preserves zero/false, rejects clearing required Fields and rejects read-only writes. Render `table-keyboard`: Tab/Shift+Tab wrap Rows, modifier+arrows reach boundaries, Delete clears, Enter edits, Esc cancels, Space expands; typing replaces only the active editable cell; editor/picker keys and outer-grid focus escape still work.
2. **Make CSV import/export safe and explicit (M).** Integration: an unknown middle header never shifts later values; quotes/newlines/Unicode round-trip; invalid cells report source line/Field without silent loss; batches have declared atomicity; numeric export is machine-readable and spreadsheet-formula text is handled safely. Render `table-csv-preview`: mapping, excluded columns, errors, cancellation, partial progress and completion match persisted Rows; export states name Row/Field scope. Coordinate relation CSV with W5; add XLSX only after this CSV contract passes.
3. **Query the complete Table, not just loaded Rows (L).** Integration: seed over 1,000 Rows with the only match after page one; search/filter/sort/count/summary/export use one authorized query and return complete consistent results, stable paging and no cross-org data. Render `table-full-query`: off-page match is found without Load more, loading/error/retry are distinct, totals never claim loaded-only values are complete. Reuse W5 query work if it lands; do not rebuild W7 ranking.
4. **Save named Grid views (L).** Integration: create/rename/duplicate/delete views; persist filters, sorts, group, hidden/order/width/height/summary config; one default common Grid survives; another Table/org cannot reference the config; unauthorized config writes fail. Render `table-saved-views`: switch two views with different layouts, reload and retain each, duplicate independently, show permission/locked-config state without disabling permitted Row edits; personal means owner-controlled configuration, not secret data.
5. **Reorder Fields without changing identity (M).** Integration: save/reload per-view order, reject duplicate/foreign/missing Field references, and retain independent primary display Field and cell values. Render `table-field-order`: drag and keyboard Move left/right both work; focus follows the Field, hidden Fields remain manageable, and freeze behavior from W1 still works after reorder. Depends on saved views.
6. **Add typed operators and nested AND/OR filter groups (L).** Integration: evaluate `(Status = Open OR Status = Review) AND Amount > 100` against the full dataset; cover empty/zero/false/date boundaries, deleted Fields, invalid operators, bounded depth and inaccessible references. Render `table-filter-groups`: add/remove/nest conditions, switch AND/OR, show readable group boundaries and active count, clear all, and fit the phone viewport. Share W5's expression contract rather than fork it.
7. **Support ordered multi-Field sorts (M).** Integration: primary/secondary keys, stable Row-ID ties, nulls-last in both directions, numeric/date ordering and Single select option-order mode work across pages. Render `table-multi-sort`: add/reorder/remove rules, display precedence and count, reload saved view, and clear all without moving keyboard focus unpredictably.
8. **Show wrapped content in taller Rows (S).** Integration: saved-view height/wrap updates round-trip and do not mutate cell text; invalid height values fail validation. Render `table-wrap-height`: long text, multiple choices and Ticket chips remain readable at tall height; compact mode truncates; virtual scrolling has no overlap/jumps; drawer and narrow-screen controls remain usable. Reuse existing virtualizer and W8 tokens.
9. **Make footer summaries type-aware and scope-correct (M).** Integration: whole-view and selected-Row totals agree with Postgres; date earliest/latest, unique count and percentages cover null/empty/zero/false with explicit denominators; unsupported functions are rejected; selection never produces a mislabeled full total. Render `table-summary-scope`: menus only offer valid functions, view-versus-selection scope is labeled, group summaries follow selected Rows, and clearing selection restores the full-view result. Depends on complete-Table query.
10. **Publish a minimal public Form view (L).** Integration: explicit publish/revoke, create-only capability and Field allowlist; server validation/defaults, rate limits and idempotent submission; no Row listing, hidden Fields, history or unauthorized linked data; revoked links and extra-field tampering fail closed. Render `table-public-form`: builder preview, anonymous published form, required/error/success states, double-submit prevention and revoked state on desktop/phone. Reuse W2 typed inputs and W3 metadata; do not confuse internal New row with public access.
