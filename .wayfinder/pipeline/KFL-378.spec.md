## Approved information architecture

### Persistent chrome

- Top retains the Team view scope selector and sidebar toggle.
- Search remains directly below the header.
- Inbox, My Tickets and expandable Recent are one compact section.
- Recent shows 3 entries at ordinary viewport heights and up to 5 when space allows.
- All navigation rows are compact (`h-7`, `text-xs`).
- Bottom contains a **single Settings nav item** linking to account Settings. It is not a disclosure section.
- Organization identity in the lower-left is the organization selector; user profile remains lower-right.
- The user profile menu contains only the user nameplate, Invitations, Trash, Shortcuts, conditional System administration, Theme and Logout. Organization switching and Settings do not appear there.

### Feature containment

- `Work` is an organization-scoped **Alpha feature**, persisted as `workEnabled`, default false.
- Settings → Organization → Features owns the Work toggle.
- When disabled, every Work surface is absent: no Work pill, Initiatives, Digest, Views, Projects, Project API calls or Project tree.
- When disabled the sidebar renders Resources directly.
- When enabled, a compact `Work / Resources` pill selects non-persistent sidebar content.

### Work mode

- Initiatives — single-page nav item.
- Digest — single-page nav item.
- Views — collapsible section listing custom views.
- Projects — collapsible section listing independently collapsible Projects.
- Each expanded Project exposes exactly:
  - Overview
  - Boards
  - Cycles
  - Resources
- Resources expands into resource types, then canonical linked resources, as a file tree.
- Item counts and disclosure chevrons occupy separate in-flow fixed columns; no absolute overlap.

### Resources mode

- Boards, Repos and Tables preserve their existing data, permissions and actions.
- Each type is a collapsible nav section item whose descendants are its resources.
- Global Resources remain canonical inventory; Project-linked entries are contextual shortcuts to canonical routes.

### People settings

- Members and Teams management remain a combined surface.
- Ctrl+K Members must target the registered organization-scoped Members/Teams route using `organization.slug`, never the nonexistent `/dashboard/settings/organization/members` path.
- A later route migration may place the surface under Organization Settings, but this ticket must not duplicate the management UI.

## API contract

`GET /api/project/sidebar?organizationId=<id>` returns only Projects the requester may view, with core identity, progress, nullable lead Team summary and authorization-filtered linked Board/Repo/Table summaries. The projection is batched and performs no per-Project HTTP/query loop.

The endpoint must not be requested unless `workEnabled` is true.
