**PASS:** KFL-365 has all four stages (`spec-review`, `implementation`, `qc-review`, `merge-check`) at `pass`; KFL-366 `spec-review` is `in-progress`.

- No Project schema/router/mounted API/web route/component/hook currently exists.
- No `project_slug_alias` machinery exists. Reuse the specific organization/board alias transaction and resolver patterns, not a new generic abstraction.

- Board detail root redirects to Kanban; Project detail root must render Overview, not redirect.

## Persistence

Create **`apps/api/drizzle/0072_project_foundation.sql`** (0071 is highest), generated snapshot, and journal entry in `apps/api/drizzle/meta/_journal.json`. Modify `apps/api/src/database/schema.ts` and `relations.ts`.

### `project`

`projectTable` columns:

| Column | Contract |
|---|---|
| `id` | CUID2 `text` PK; opaque immutable ID. |
| `organization_id` | non-null organization FK, cascade delete/update. |
| `slug` | non-null canonical route identity. |
| `name` | non-null text. |
| `icon`, `color` | nullable text. |
| `summary` | non-null outcome summary. |
| `description`, `success_criteria` | nullable text. |
| `status` | non-null default `planned`; check `planned|started|completed|canceled`. |
| `priority` | nullable text; reuse existing Ticket priority vocabulary/validator. |
| `lead_user_id` | non-null user FK (`restrict` delete, cascade update). |
| `lead_team_id` | nullable team FK (`set null` delete, cascade update). |
| `start_date`, `target_date` | nullable ISO date-only text. |
| `org_privilege` | nullable per-resource baseline; NULL follows organization default. |
| `archived_at` | nullable timestamp. |
| `archived_by` | nullable user FK (`set null`, cascade update). |
| `created_at`, `updated_at` | non-null default timestamps; `updatedAt.$onUpdate`. |
| `created_by` | non-null user FK (`restrict`, cascade update). |

Constraints/indexes: composite unique `(organization_id,id)`; case-insensitive unique `(organization_id, lower(slug))`; indexes `(organization_id, archived_at)`, `lead_user_id`, and an FK-supporting `lead_team_id` index if generation does not supply one. Controllers verify the lead has active membership and lead team belongs to the same organization; normal FKs cannot enforce that.

### `project_slug_alias`

`projectSlugAliasTable`: CUID2 `id`; non-null `organization_id` FK and `project_id` FK (both cascade); non-null `slug`; non-null `created_at`; case-insensitive unique `(organization_id, lower(slug))`; index `project_id`.

`renameProjectSlug()` is one transaction: lock Project, normalize/validate slug, reject canonical/alias ownership by another Project (409), insert old canonical slug as alias, delete this Project alias equal to new slug, update canonical slug. Historical aliases remain permanently reserved even after later rename.

## Required permission and identity cutover

- In `apps/api/src/resource-access.ts`, add `project` to `RESOURCE_TYPES`, `ResourceType`, and `RESOURCE_TABLES` mapping to `projectTable`.
- Change resource-grant table check to include `project`; update resource-grant router/OpenAPI enum. Keep existing grant precedence and team inheritance.
- Add Project lookup to `lookupOrganizationId`; export `organizationAccess.fromProject(idKey = "id")`.
- Add `project: ["create", "read", "update", "delete", "share"]` adjacent to Board actions in `packages/permissions/src/index.ts`; update role tests/seed expectations.
- Create a server-owned Project slug resolver. Resolve canonical case-insensitively, then alias join; apply `requireResourcePrivilege(... project, view)` before returning data. Missing/cross-org/inaccessible IDs and slugs return the identical `404 Project not found`. Alias response includes canonical slug and `usedSlugAlias`; client replaces URL.
- Direct reads/mutations need both Organization action permission and resource privilege. `requireOrganizationPermission` alone ignores a per-resource baseline/grant.

## API

Create `apps/api/src/project/index.ts`; mount in `apps/api/src/index.ts` as `api.route("/project", project)`. All endpoints use `describeRoute` and Valibot.

| Endpoint | Middleware | Controller |
|---|---|---|
| `GET /project?organizationId&includeArchived` | `fromQuery`, `project:read` | `list-projects`; visibility-filtered; archived excluded by default. |
| `POST /project` | `fromBody`, `project:create` | `create-project`; required `organizationId,name,summary,leadUserId`; status defaults planned; normalize supplied/generated slug. |
| `GET /project/resolve?organizationId&slug` | `fromQuery`, `project:read`, view guard | `resolve-project`; canonical projection and alias flag; no leak. |
| `GET /project/:id` | `fromProject`, `project:read`, view guard | `get-project`. |
| `PUT /project/:id` | `fromProject`, `project:update`, edit guard | `update-project`; explicit full editable payload: name, summary, status, priority, icon/color, description, successCriteria, lead user/team, dates, orgPrivilege. No slug here. |
| `PUT /project/:id/slug` | `fromProject`, `project:update`, edit guard | `rename-project-slug`. |
| `PUT /project/:id/archive` | `fromProject`, `project:update`, edit guard | `archive-project`; set archive timestamp/actor only. |
| `PUT /project/:id/unarchive` | same | `unarchive-project`; clear archive fields only. |

Controllers: `create-project`, `list-projects`, `get-project`, `resolve-project`, `update-project`, `rename-project-slug`, `archive-project`, `unarchive-project`, shared `project-projection` and `validate-project-leads`. Every mutation emits existing org-scoped push/event and invalidates `projects`, `project`, sidebar families. Projections include lead display data, archive state, `progress: null`, `health: null`; no linked child data.
