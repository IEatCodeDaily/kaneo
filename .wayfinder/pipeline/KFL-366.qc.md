## Gate

## Spec compliance

The new Project schema, alias transaction/resolver, resource lattice, organization-access lookup, permission vocabulary, mounted `/api/project` routes, Overview-root routes, sidebar placement, and presentation-only `progress`/`health` fields substantially follow the S1 spec. **REWORK.** The implementation contains release-blocking migration history damage, violates the existing KFL-365 regression guard, omits four specified component scenarios, and does not implement the specified mutation event/query invalidation behavior.

## Named audit targets

### a. Deleted `0037_tiny_raza.sql` and journal mutation — REWORK

- `apps/api/drizzle/0037_tiny_raza.sql` is deleted and its journal entry is removed.
- The file was introduced by commit `7f5a0c02f44c0d15cd9cb444d1990e740c8f301b` on 2026-08-15. It is contained by release tags `v2.19.0` through `v2.22.0` and `upstream/main`; this is shipped migration history, not an uncommitted local defect.
- The migration modifies the existing legacy `project` table using `workspace_id`; removing it changes Drizzle's ordered migration set. Databases that recorded 0037 retain a journal row not represented by source; databases that have not run it receive a different history. Deleting deployed migrations is unacceptable.
- Restore 0037 and its exact journal entry. Repairing a migration chain requires a new forward-only migration or an explicit, production-reviewed remediation plan, not history rewriting.
